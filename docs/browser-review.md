# 화면 전체 점검 — 2026-11-09

프런트엔드 `http://127.0.0.1:5173`와 FastAPI `http://127.0.0.1:8000`을 실행하고 Chromium에서 입력부터 결과·초기화까지 확인했다. 데스크톱 1280×900, 모바일 크기 390×844를 사용했다. 모바일은 브라우저 크기·터치 에뮬레이션이며 실기기 검사는 아니다.

## 결과

- 테스트 응답을 사용한 브라우저 흐름: 6개 시나리오 × 2개 화면 크기, **12건 통과**.
- 실제 Gemini 호출: 데스크톱 브라우저에서 가상 인증번호 요구 예시 1건, **통과**. 테스트 전체 약 4.3초(브라우저 조작 포함)였고 의심 상태·인증정보 요구·원문 강조·공식 출처·초기화를 확인했다.
- 프런트엔드 단위 검사 **6건 통과**, TypeScript 검사와 배포 빌드 통과.
- 실제 화면 스크린샷을 보고 데스크톱·모바일의 한글 표시와 배치를 확인했다. 검사한 결과 화면에는 가로 넘침이 없었다.

브라우저 시나리오는 다음을 확인한다.

1. 동의 전 분석 요청이 없고, 전송 데이터에는 가림된 전화·링크만 포함된다. 내용을 수정하면 다시 동의해야 한다.
2. 상태·행위 태그·원문·이유·공식 링크가 표시되고 원문 강조가 입력과 일치한다. 초기화하면 입력·결과가 지워진다.
3. 다화자 예시에서 메시지를 삭제·추가·수정하고 입력 화면으로 돌아갈 수 있다.
4. 검토 화면에서 추가한 개인정보를 재가림하고 다시 동의를 받는다.
5. 한도 오류를 정상 분석 결과로 위장하지 않으며, 수정·재시도 가능한 입력이 남는다. 빈 입력·길이 초과는 전송 전에 안내한다.
6. 분석 중 초기화하면 늦게 도착한 응답이 결과 화면을 복구하지 않는다. 검사 중 브라우저 런타임 오류가 없었고 localStorage·sessionStorage에 대화가 저장되지 않았다.

## 발견한 문제와 수정

수정 후 재가림할 때 서로 다른 전화번호가 모두 `[전화1]`로 표시되는 문제를 실제 브라우저에서 재현했다. 기존 가림 토큰의 번호를 먼저 예약하고 새 번호부터 할당하도록 수정했다. 서로 다른 메시지·화자에 있는 기존 토큰도 고려하며, 같은 새 번호는 같은 토큰으로 가린다. 과거 원문 값은 저장하지 않으므로 삭제한 원래 번호와 새로 입력한 번호가 같은지까지 복원하지는 않는다.

검사 환경에 한글 시스템 글꼴이 없어 문자가 네모로 보였다. Noto Sans KR 가변 글꼴을 npm 의존성으로 포함하고 앱 서버에서 제공하도록 수정했다. 글꼴을 받기 위해 외부 CDN에 접속하지 않는다. 라이선스는 `frontend/public/fonts/OFL.txt`에 포함했다.

## 재현

백엔드와 프런트엔드를 먼저 실행하고 `frontend/`에서 다음 명령을 사용한다.

```bash
npx playwright install --with-deps chromium
npm run test:e2e -- flow.spec.ts
# 이 명령만 실제 외부 Gemini 호출을 허용한다.
SCAMCHECK_LIVE_E2E=1 npm run test:e2e -- live.spec.ts --project=desktop
```

현재 검사 환경은 관리자 암호 없이 진행하기 위해 Chromium을 `/tmp/scamcheck-playwright`, 누락된 라이브러리를 `/tmp/scamcheck-browser-libs`에 설치했다. 그 환경에서 재실행할 때는 다음 변수를 사용한다.

```bash
LD_LIBRARY_PATH=/tmp/scamcheck-browser-libs/usr/lib/x86_64-linux-gnu PLAYWRIGHT_BROWSERS_PATH=/tmp/scamcheck-playwright npm run test:e2e -- flow.spec.ts
```

브라우저 스크린샷은 Git에서 제외한 `artifacts/browser/`에 저장했다. `desktop-input.png`, `desktop-result.png`, `mobile-input.png`, `mobile-result.png`는 화면 테스트 응답을 사용한 검사이고, `live-gemini-result.png`는 실제 Gemini 응답이다. 오류 검사는 모델 대역을 쓰며 실제 API의 모든 장애 상황을 재현한 것은 아니다.

## 직접 확인할 순서

`http://127.0.0.1:5173`에서 가상 예시 **인증번호 요구 → 가림 내용 확인 → 전송 동의 → 의심 신호 분석**을 실행한다. 이어서 리딩방 출금 상담과 사기 예방 안내를 확인하고, 문구의 이해도·버튼 위치·대화 편집 편의성을 살펴본다. 실제 개인정보·민감 대화는 무료 시연에 사용하지 않는다.

오늘 저녁 로컬 시연의 핵심 흐름은 동작 확인을 마쳤다. 사용자 사용감 확인, 실제 모바일·다른 브라우저 검증, 전체 개발·보류 성능 비교와 공개 배포 준비는 후속 작업이다.
